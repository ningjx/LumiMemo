## 重大事故排查：Demo「闪退」链式崩溃（RO_E_CLOSED 僵尸链）

- **现象**：用户双击 LumiText.Demo.exe 闪退。WER 显示 5 次崩溃全是 0xc000027b（stowed）/combase **0x80040111 RO_E_CLOSED**，Microsoft.UI.Xaml.dll 同偏移。
- **真相（逐层排除）**：① 不是应用 bug——S2/M1 时代无任何崩溃记录，主程序 LumiMemo.WinUI（同 WASDK 2.5.1 自包含）同时段运行正常；② 不是 exe 路径/文件名（改名副本照崩）；③ 不是 dotnet 代码（阴影构建 0 警 0 错）；④ **是我在 19:22 用 taskkill /F 强杀 perf 实例，触发 WER 崩溃快照僵尸（受保护、taskkill/Stop-Process 均拒绝访问、WerSvc 重启需管理员）——此后同 exe 的每次启动都 RO_E_CLOSED 自杀**：僵尸少时 ~40s 死亡，僵尸累积后 ~1s 死亡。用户 21:33 的双击是僵尸链受害者。
- **教训（硬规则）：自动化里绝不用 taskkill /F / Stop-Process -Force 杀 WinUI 实例**——用 `$p.CloseMainWindow()` 优雅关闭；WER 快照僵尸会连锁毒化后续所有启动，且只有重启/注销能清。
- **当前状态**：僵尸 PID 37036 仍在（锁定原 exe 输出路径，正常构建会 MSB3027）；代码已验证健康（`-o artifacts/shadow-build` 阴影构建通过）；App.xaml.cs 加了 UnhandledException 日志探针（只记录不吞，crashlog.txt；该故障不走 XAML 托管通道，探针未触发）。**恢复方法：重启或注销系统清僵尸，之后一切正常。**
- artifacts 留档：repro/repro2/shadow-build（运行副本）、ps-out.txt、wer-detail.txt、final-check.txt、zombie.txt。
