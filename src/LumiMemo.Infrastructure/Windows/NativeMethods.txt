// CsWin32 的输入清单：一行一个 API / 类型 / 常量。
//
// 为什么用 CsWin32 而不是手写 [DllImport]：手写签名的错误是最容易出、
// 也最难查的一类 bug。CsWin32 从元数据生成，类型安全（§2.2）。
//
// 目前只有 MonitorEnumerator（显示器枚举与稳定设备路径）在消费本清单。
// 加 API 前先想清楚谁会用它——清单里的每一项都会生成一份 P/Invoke 声明。

// ---- 显示器与 DPI ----
EnumDisplayMonitors
// CsWin32 把 GetMonitorInfo 映射到 MONITORINFO 那个重载，
// 而我们需要 MONITORINFOEXW 里的 szDevice（"\\\\.\\DISPLAY1"）才能接着问
// EnumDisplayDevices 要稳定设备路径，所以把结构体也显式列上。
MONITORINFOEXW
GetMonitorInfo
GetDpiForMonitor
// displays 表要求键是 "\\?\DISPLAY#DEL41A6#...#{...}" 这种跨会话稳定的设备接口路径，
// 而 GetMonitorInfo 只给得出 "\\.\DISPLAY1"（§13.8 明说不该用它当身份）。
// 从物理设备名映射到设备接口路径只有 EnumDisplayDevices 做得到。
EnumDisplayDevices
DISPLAY_DEVICEW
// EnumDisplayDevices 靠 EDD_GET_DEVICE_INTERFACE_NAME 决定 DeviceID 里
// 填的是设备接口路径还是 MONITOR\... 那种卷名；MONITORINFOF_PRIMARY 用来认主显示器。
EDD_GET_DEVICE_INTERFACE_NAME
MONITORINFOF_PRIMARY
