// CsWin32 的输入清单：一行一个 API / 类型 / 常量。
// 内容与文档附录 D「Win32 API 清单」对应，加 API 前请先改那里的表格。
//
// 为什么用 CsWin32 而不是手写 [DllImport]：手写签名的错误是这个项目最容易出、
// 也最难查的一类 bug（SetWindowLongPtr 在 32 位下不存在、DwmSetWindowAttribute
// 的参数类型等）。CsWin32 从元数据生成，类型安全（§2.2）。
//
// 注意：这里只列**函数**。WM_* 消息常量与 MONITORINFO 之类的结构体会在
// CsWin32 生成上述函数时按需自动带出；真到了写 WndProc 的时候发现缺哪个再往这里加。

// ---- D.1 窗口外观与 DWM ----
DwmSetWindowAttribute
DwmExtendFrameIntoClientArea
// 附录 D.1 写的是 GetWindowLongPtr / SetWindowLongPtr（不带后缀）。CsWin32 的元数据里
// 只有 GetWindowLongPtrW / GetWindowLongPtrA 这一对，它的友好名表没有收录这两个，
// 直接写不带后缀的名字会报 PInvoke001。本项目只做 Unicode，因此固定用 W 版本。
GetWindowLongPtrW
SetWindowLongPtrW
SetWindowPos
GetWindowRect
SetForegroundWindow
GetForegroundWindow
AttachThreadInput
GetWindowThreadProcessId
GetCurrentThreadId
ShowWindow

// ---- D.2 消息处理 ----
// WM_NCHITTEST 命中时先取系统判定结果（§13.3）
DefWindowProc

// ---- D.3 显示器与 DPI ----
MonitorFromPoint
// 附录 D.3 只写了 GetMonitorInfo。CsWin32 把这个名字映射到 MONITORINFO 那个重载，
// 而我们需要 MONITORINFOEXW 里的 szDevice（"\\\\.\\DISPLAY1"）才能接着问
// EnumDisplayDevices 要稳定设备路径，所以把结构体也显式列上。
MONITORINFOEXW
GetMonitorInfo
EnumDisplayMonitors
GetDpiForMonitor
GetDpiForWindow
// 附录 D.3 漏了这一条，但 §8.3 的 displays 表要求键是
// "\\?\DISPLAY#DEL41A6#...#{...}" 这种跨会话稳定的设备接口路径，
// 而 GetMonitorInfo 只给得出 "\\.\DISPLAY1"（§13.8 明说不该用它当身份）。
// 从物理设备名映射到设备接口路径只有这条 API 做得到。
EnumDisplayDevices
DISPLAY_DEVICEW
// 上面两条 API 各带一个 0x1 的标志位：EnumDisplayDevices 靠
// EDD_GET_DEVICE_INTERFACE_NAME 决定 DeviceID 里填的是设备接口路径还是
// MONITOR\... 那种卷名；MONITORINFOF_PRIMARY 用来认主显示器。
// 值都恰好是 1，手抄成 0x1 不会当场出错——正是这种「抄错了也照样跑」的常量
// 该让 CsWin32 从元数据里给，而不是自己敲。
EDD_GET_DEVICE_INTERFACE_NAME
MONITORINFOF_PRIMARY

// ---- D.4 热键与输入 ----
RegisterHotKey
UnregisterHotKey
